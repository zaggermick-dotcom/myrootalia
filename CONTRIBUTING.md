# Guide de Contribution

Merci de votre intérêt pour contribuer à **myrootalia** ! 🙏

## 📋 Code de Conduite

En participant à ce projet, vous acceptez de respecter un comportement respectueux et professionnel envers tous les contributeurs.

## 🎯 Comment contribuer

### Signaler un bug 🐛

1. Vérifiez que le bug n'a pas déjà été signalé dans les [issues](https://github.com/zaggermick-dotcom/myrootalia/issues)
2. Créez une nouvelle issue avec le label `bug`
3. Décrivez le problème de manière claire et détaillée
4. Incluez des étapes pour reproduire le bug

### Proposer une fonctionnalité ✨

1. Ouvrez une issue avec le label `enhancement` ou `feature`
2. Décrivez la fonctionnalité souhaitée
3. Expliquez le cas d'usage et les bénéfices

### Soumettre une Pull Request 🔄

1. Fork le dépôt
2. Créez une branche feature (`git checkout -b feature/AmazingFeature`)
3. Committez vos changements (`git commit -m 'Add some AmazingFeature'`)
4. Poussez votre branche (`git push origin feature/AmazingFeature`)
5. Ouvrez une Pull Request

## 📝 Conventions

### Commits
- Utiliser des messages clairs et descriptifs
- Préfixer par un type: `feat:`, `fix:`, `docs:`, `style:`, `refactor:`, `test:`, `chore:`

Exemple:
```
feat: Add user authentication
fix: Resolve memory leak in data processing
docs: Update installation instructions
```

### Branches
- `main` - branche de production
- `develop` - branche de développement
- `feature/*` - nouvelles fonctionnalités
- `fix/*` - corrections de bugs

## 🧪 Tests

Avant de soumettre une PR:
- Testez vos changements localement
- Assurez-vous que tous les tests passent
- Ajoutez des tests pour les nouvelles fonctionnalités

## 📚 Documentation

- Maintenez la documentation à jour
- Incluez des commentaires pour le code complexe
- Mettez à jour le README si nécessaire

## ❓ Questions

Si vous avez des questions, ouvrez une issue ou contactez un mainteneur.

---

Merci de contribuer à myrootalia ! 🎉
